# Deploying CropGuard on AWS

Everything is described in one CloudFormation template, [`infra/aws/cropguard.yaml`](../infra/aws/cropguard.yaml),
so the whole environment is created, updated and deleted as one unit and can be reviewed like code.

## What gets created

```
                        HTTPS (*.cloudfront.net)
   Farmer's browser ──────────────────────────▶ CloudFront
                                                  │  /assets/*  cached at the edge
                                                  │  /api/*     passed through, never cached
                                                  ▼ HTTP :80
                       ┌───────────────── EC2 (Amazon Linux 2023, Docker) ─────────────────┐
                       │  web (nginx + React) ─▶ api (Node) ─▶ ml (FastAPI + ONNX)          │
                       │                           │                                        │
                       │                           └─▶ mongo (EBS volume, encrypted)        │
                       └──────────┬─────────────────────────────┬───────────────────────────┘
                                  │ IAM instance role            │ IAM instance role
                                  ▼                              ▼
                     S3 bucket (crop photos)          Secrets Manager
                     private · encrypted · TLS only   JWT secret · admin password
```

| Resource | Purpose | Security notes |
|---|---|---|
| `AWS::EC2::Instance` (t3.medium) | Runs the four containers with Docker Compose | Encrypted 30 GB gp3 volume; IMDSv2 required; no key pair, no SSH port |
| `AWS::EC2::EIP` | Fixed public IP for the server | |
| `AWS::EC2::SecurityGroup` | Allows inbound HTTP 80 only | Shell access goes through Systems Manager, not port 22 |
| `AWS::S3::Bucket` | Stores uploaded photos and heatmaps | Public access blocked, AES-256 encryption, bucket policy denies non-TLS access, retained if the stack is deleted |
| `AWS::IAM::Role` | Lets the app use S3 and read its secrets | Only `PutObject/GetObject/DeleteObject` on `uploads/*`, and `GetSecretValue` on its two secrets. No access keys anywhere |
| `AWS::SecretsManager::Secret` ×2 | JWT signing secret and first admin password | Generated by AWS; never in the template, user data or Git |
| `AWS::CloudFront::Distribution` | HTTPS, HTTP/2 and 3, caching of static assets | Viewers redirected to HTTPS |

The browser loads photos through short-lived (1 hour) presigned S3 URLs, so the bucket never needs to be public.

## Prerequisites

1. An AWS account and the [AWS CLI v2](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html),
   configured with `aws configure` (or `aws sso login`) for a user allowed to create EC2, S3, IAM, Secrets Manager
   and CloudFront resources.
2. The repository pushed to GitHub. The server clones it, so it must be public, or change `RepoUrl` to a URL
   the server can reach.
3. Optional: a free [data.gov.in](https://data.gov.in) API key for live mandi prices.

## Deploy

From the repository root (Git Bash, WSL, macOS or Linux):

```bash
./infra/aws/deploy.sh
```

Defaults: stack `cropguard`, region `ap-south-1` (Mumbai), `t3.medium`. To change them:

```bash
STACK=cropguard-demo REGION=ap-south-1 ./infra/aws/deploy.sh \
  InstanceType=t3.small AdminEmail=you@example.com DataGovApiKey=YOUR_KEY
```

The first deploy takes **10–20 minutes**. On first boot the server installs Docker, clones the repo, fetches its
secrets, writes `.env`, builds the images and starts them. CloudFormation waits until `/api/health` answers
before it reports success; if anything fails the stack rolls back and the log is in
`/var/log/cropguard-bootstrap.log` on the instance.

When it finishes, the script prints the stack outputs:

| Output | Use |
|---|---|
| `AppUrl` | Open in a browser. CloudFront can take a few more minutes to answer the first time. |
| `AdminEmail` | The first admin account |
| `AdminPasswordCommand` | Run it to read the generated admin password |
| `InstanceId` | For Session Manager and updates |
| `UploadsBucketName` | Where photos are stored |

Sign in as the admin, then **change the password** from *Profile & security*.

## Ship an update

Push to `main`, then:

```bash
./infra/aws/update.sh
```

It runs `git pull` and `docker compose up -d --build` on the server through Systems Manager and prints the result.
MongoDB data and photos are untouched.

## Operate

```bash
# Shell on the server (no SSH key needed)
aws ssm start-session --target <InstanceId> --region ap-south-1

# On the server
cd /opt/cropguard
sudo docker compose ps
sudo docker compose logs -f api ml
sudo docker compose exec mongo mongosh cropguard --eval 'db.users.countDocuments()'
```

| Task | How |
|---|---|
| Back up the database | `sudo docker compose exec mongo mongodump --archive --gzip > backup.gz` then `aws s3 cp backup.gz s3://<bucket>/backups/`, or enable scheduled EBS snapshots with Data Lifecycle Manager |
| Use a managed database | Create a MongoDB Atlas cluster, add `MONGO_URI=…` to `/opt/cropguard/.env`, `docker compose up -d` |
| Live market prices | Add `DATA_GOV_API_KEY=…` to `.env` and restart the `api` container |
| Custom domain | Add an ACM certificate in us-east-1 and an alias to the CloudFront distribution, then point DNS at it |
| Larger traffic | Move to a bigger instance type, or split the `ml` container onto its own instance behind the same API contract |

## Cost estimate

Approximate on-demand prices in ap-south-1 in 2026. Check the AWS pricing calculator for current figures.

| Item | Approx. per month |
|---|---|
| EC2 t3.medium, always on | ~US$ 30 |
| EBS 30 GB gp3 | ~US$ 2.5 |
| Public IPv4 address | ~US$ 3.6 |
| Secrets Manager (2 secrets) | ~US$ 0.8 |
| S3 storage and requests | under US$ 1 for thousands of photos |
| CloudFront | Free tier covers 1 TB transfer per month |
| **Total** | **about US$ 35–40**; about US$ 20 on t3.small |

The free-tier t2/t3.micro (1 GB RAM) is too small to build and run MongoDB, the API and the ML model together.
Stop the instance when it is not needed to pay only for storage.

## Tear down

```bash
aws cloudformation delete-stack --stack-name cropguard --region ap-south-1
```

The S3 bucket is **retained** so photos are not lost by accident. Empty and delete it by hand if you no longer need it.

## Run the same stack anywhere else

`docker-compose.yml` is not AWS-specific. On any Linux server with Docker:

```bash
git clone https://github.com/bharathvaj125/Cropguard.git && cd Cropguard
cp .env.example .env    # set JWT_SECRET and SEED_ADMIN_PASSWORD
docker compose up -d --build
```
